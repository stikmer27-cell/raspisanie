# Расписание ВКИ НГУ — Android-приложение

Приложение само скачивает PDF с [ci.nsu.ru/education/schedule](https://ci.nsu.ru/education/schedule/),
разбирает его прямо на телефоне и присылает уведомления:

- **вечером** (по умолчанию 20:00) — пары на завтра;
- **утром** (по умолчанию 07:00) — пары на сегодня;
- **сразу**, если уже присланное расписание поменяли (сайт проверяется примерно раз в 30 минут).

Никаких серверов и аккаунтов: всё работает на телефоне. GitHub нужен, чтобы собрать APK и раздавать обновления.

При первом запуске приложение просит вписать группу (понимает «2507сб1», «2507 СБ1», «2507sb1», «В2507са1»).
Сверху — переключатель «день / ночь» (светлая и чёрная тема), в настройках можно выбрать «Авто».

Если день начинается не с первой пары, это видно сразу: над списком крупно «Ко второй паре — 10:45»,
на месте пустой пары — прочерк «Пары нет», в кнопке дня — пустой кружок вместо точки.
То же в виджете и в уведомлениях («Завтра…: ко второй паре (10:45)»), а если первую пару убрали
уже после уведомления — придёт «⚠️ …: теперь ко второй паре».

## Новости и сессия

Внизу три вкладки: **Расписание · Новости · Сессия**. Всё берётся с сайта колледжа (без входа):

- **Новости** — новости и объявления ci.nsu.ru; о новой — уведомление (свежая ещё и карточкой над расписанием).
- **Сессия** — расписание экзаменов и пересдач и вопросы к зачётам **для своей группы**. Группа ищется
  по названию файла («Химия (2501а, 2507а-д) ДЗ») или внутри PDF (у прошлогоднего «1 курса» там уже другие
  группы). Когда выложат пересдачи, приложение спросит «остались долги?»: отмеченные предметы оно ищет
  в расписании пересдач и пишет в уведомлении, есть ли они там.
- **Пособия колледжа** — в «Сессии» и прямо у пар подходящего предмета (например, «Тригонометрия» у математики).

Новости проверяются вместе с расписанием, страницы сессии и пособий — раз в несколько часов (трафик мизерный).

## Автообновление

Приложение раз в 6 часов и при каждом открытии смотрит последний релиз этого репозитория. Новая версия
скачивается, проверяется (тот же пакет, та же подпись, контрольная сумма) и ставится сама, когда
из приложения вышли. Для этого «Расписанию» нужно один раз разрешить установку обновлений
(приложение само предложит: плашка «Включи автообновление» или 🔔 → Установка обновлений). После этого
на Android 12+ обновления ставятся без вопросов; без разрешения — придёт уведомление «нажми, чтобы установить».

Ключей и входа не нужно: релизы открытые. Чужой APK поверх не встанет — Android принимает обновление
только с той же подписью, а ключ подписи хранится в секретах репозитория (`KEYSTORE_B64`), не в коде.

## Установка

1. Скачай APK: вкладка **Releases** этого репозитория → последний релиз → `raspisanie-1.0.N.apk`.
2. Открой его на телефоне. Android спросит разрешение «устанавливать из этого источника» — разреши.
   Если Play Защита предупредит о неизвестном разработчике — «Всё равно установить».
3. Открой **Расписание**, впиши свою группу, разреши уведомления.
4. В приложении нажми 🔔 → **Работа в фоне → Разрешить**, чтобы телефон не усыплял проверки.
   На Xiaomi/Redmi/POCO ещё: Настройки → Приложения → Расписание → **Автозапуск** — включить,
   **Контроль активности** — «Нет ограничений».
5. Там же — **Тестовое уведомление**, чтобы проверить, что всё приходит.

Дальше приложение обновляется само. Все версии подписаны одним и тем же ключом, поэтому встают поверх старой.

## Как устроено

```
android/app/src/main/assets/
  engine.js      разбор PDF (pdf.js) + логика уведомлений + самопроверки
  extras.js      новости, сессия, вопросы к зачётам, пособия (страницы сайта колледжа)
  sections.js    вкладки «Новости» и «Сессия»
  worker.html    невидимая страница для фоновой проверки
  index.html, app.js, style.css, stickers.js   интерфейс
  pdf.min.js, pdf.worker.min.js                 pdf.js (Mozilla, Apache-2.0)
android/app/src/main/java/ru/stikmer/raspisanie/
  CheckWorker.kt  фоновая проверка (WorkManager, ~раз в 30 минут)
  Scheduler.kt    будильники на вечер/утро, перезапуск после перезагрузки
  Engine.kt       запуск движка в невидимом WebView
  Notifier.kt     уведомления
  Updater.kt      автообновление из релизов (PackageInstaller)
  ScheduleWidget.kt виджет на главный экран
  MainActivity.kt экран приложения
tests/            тесты движка на реальных PDF (запускаются перед каждой сборкой)
```

PDF — это таблица с объединёнными ячейками, поэтому движок разбирает её по геометрии:
находит линии таблицы, собирает ячейки, раскладывает текст по ячейкам, а ячейки — по группам,
дням и парам.

### Защита от ошибок в расписании

Каждый разбор проходит независимые самопроверки: весь текст из таблицы должен попасть в какую-то пару;
текст в колонке группы на строке пары должен совпасть с разобранной парой; день недели — с датой;
номера пар идут подряд, время совпадает со звонками; в ячейке на несколько групп или пар не должно быть
отдельных текстов для разных групп/пар; у записи должно быть название (а не обрывок «Иванов И.И. 402»).
Если что-то не сходится, приложение не молчит, а показывает над днём «Сверь этот день с PDF» и кнопку PDF.

Трудные места реальных PDF, которые разбор обрабатывает (и на которые есть тесты): в PDF не нарисована
граница между группами (ячейка делится по тому, над какими колонками стоит каждый текст); текст не влез
в ячейку и вылез на строку следующей пары (возвращается к своему абзацу); случайный символ в пустой ячейке.
Разобранные PDF кэшируются с номером версии разбора: после обновления приложения всё разбирается заново.

`tests/run.mjs` перед каждой сборкой проверяет:
- все 7 PDF (все курсы) разбираются без замечаний;
- расписание одной группы (2507сб1) совпадает с эталоном, сверенным с PDF вручную;
- логику уведомлений (вечер, утро, изменения, выходные, «ещё не выложили»);
- трудные места PDF и раскладку текста на предмет / вид / преподавателя / аудитории;
- кэш: тот же PDF не скачивается и не разбирается повторно, pdf.js без нужды не грузится;
- что самопроверки ловят 9 видов намеренной порчи движка.

- что PDF разбирается и в старом WebView (Chrome 113) — с нашими полифилами (`assets/polyfills.js`).

Если тесты не прошли — APK не собирается.

```bash
cd tests && npm install && node run.mjs
```

### Проверка на настоящем Android

Workflow **«Проверка на эмуляторе»** (запускается вручную: Actions → Run workflow) ставит последний APK
на эмулятор Android 14 со старым WebView и проходит сценарий: ввод группы → расписание по дням →
тестовое уведомление → кнопка «Назад» → переключение темы → автообновление → виджет. Читаемость текста
в обеих темах проверяется по пикселям скриншотов. Для автообновления сначала ставится та же программа
с номером версии 1 — она должна сама скачать и поставить релиз. Скриншоты и логи — в артефакте `device-test`.
